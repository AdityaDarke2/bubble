PART 0: READ FIRST — CONCEPTS

0.1 What is a log?
A log is a record of events written by an application or server. Think
of it as a CCTV recording of software: every time something happens
(a page is requested, a user logs in, an error occurs), one line is
written. A single line from a web server log looks like this:

10.0.0.21 - - [12/Oct/2026:09:00:05 +0530] "GET /home HTTP/1.1" 200 1500 "-" "Mozilla/5.0"

It tells us: WHO (IP address 10.0.0.21), WHEN (12 Oct 2026, 09:00),
WHAT (a GET request for /home), RESULT (status code 200), and SIZE
(1500 bytes).

HTTP status codes to remember:
   200 = OK (success)
   301 = Moved (redirect)
   401 = Unauthorized (login failed or missing)
   403 = Forbidden (not allowed)
   404 = Not Found (page does not exist)
   500 = Server Error (something broke on the server)

0.2 Monitoring vs Logging
In the last lab, Nagios told us THAT something is wrong (a service
turned red). Logs tell us WHY it went wrong. Companies use both
together: monitoring raises the alarm, logs help find the cause.

0.3 The "needle in a haystack" problem
A small website has one server and one log file; you can just open it.
A big company has hundreds of servers, each producing millions of log
lines per day. Logging in to each server and reading files is
impossible. The solution is CENTRALIZED LOGGING: collect logs from all
servers into one place, make them searchable, and show them as charts.

0.4 The ELK Stack
ELK is a group of three open-source tools from Elastic. Think of a
restaurant:
   - Logstash is the prep cook. It takes raw ingredients (raw logs),
     cleans and cuts them (processes them).
   - Elasticsearch is the storage room with a super-fast manager. It
     stores everything and finds anything you ask for in milliseconds.
   - Kibana is the waiter and menu card. It presents the data to you
     as searches, charts and dashboards.

Flow:  Log file  →  Logstash  →  Elasticsearch  →  Kibana

0.5 Elasticsearch in detail
- It is a search engine, like Google but for your own data.
- It stores data as JSON documents. One log line becomes one document.
- A group of documents is called an INDEX (like a cupboard that holds
  many files).
- You talk to it using a REST API over HTTP, on port 9200.

0.6 Logstash in detail
- Logstash is a data pipeline with three stages:
     INPUT  = where the data comes from (a file, network, database)
     FILTER = clean and structure the data
     OUTPUT = where the data goes (here, Elasticsearch)
- The most important filter is GROK. A raw log line is one long piece
  of text. Grok splits it into separate named fields (clientip, verb,
  request, response...). Without this, we could not search "only 401
  errors" or draw a chart by status code.

0.7 Kibana in detail
- Kibana is a web dashboard that runs in the browser on port 5601.
- Discover = search and filter raw log events (like Google search).
- Dashboard / Visualizations = bar charts, pie charts, and graphs
  (like a car's speedometer: raw engine data shown in a readable way).

0.8 Why is this "open source"?
All three tools were open source and are widely used in industry.
Interesting case study: in 2021 Elastic changed Elasticsearch's license,
and Amazon created its own fork called OpenSearch. This shows how
licenses and business decisions shape open-source projects.

Step 3. Create the Logstash pipeline file. Run: nano logstash.conf
Paste exactly this:

input {
  file {
    path => "/usr/share/logstash/input/portal_access.log"
    start_position => "beginning"
    sincedb_path => "/dev/null"
  }
}

filter {
  grok {
    match => { "message" => "%{COMBINEDAPACHELOG}" }
    ecs_compatibility => disabled
  }
  date {
    match => [ "timestamp", "dd/MMM/yyyy:HH:mm:ss Z" ]
  }
  mutate {
    convert => { "response" => "integer" "bytes" => "integer" }
  }
}

output {
  elasticsearch {
    hosts => ["http://elasticsearch:9200&quot;]
    index => "portal-logs-%{+YYYY.MM.dd}"
  }
  stdout { codec => rubydebug }
}

Step 4. Create the Docker Compose file. Run: nano docker-compose.yml
Paste exactly this (spaces matter in YAML; do not use tabs):

services:
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.15.0
    container_name: elasticsearch
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - ES_JAVA_OPTS=-Xms512m -Xmx512m
    ports:
      - "9200:9200"

  logstash:
    image: docker.elastic.co/logstash/logstash:8.15.0
    container_name: logstash
    environment:
      - LS_JAVA_OPTS=-Xms256m -Xmx256m
    volumes:
      - ./logstash.conf:/usr/share/logstash/pipeline/logstash.conf
      - ./portal_access.log:/usr/share/logstash/input/portal_access.log
    depends_on:
      - elasticsearch

  kibana:
    image: docker.elastic.co/kibana/kibana:8.15.0
    container_name: kibana
    environment:
      - ELASTICSEARCH_HOSTS=http://elasticsearch:9200
    ports:
      - "5601:5601"
    depends_on:
      - elasticsearch

- Index not found? Wait 1 minute and run Step 14 again.
- Container exited? Run "docker logs elasticsearch" to see why. The
  most common cause is Step 8 not being done.

  "docker ps" and stop old containers.
